# China Battery Brief — 整理层：scan:digest 指令

> 用途：抓取层（`npm run scan:sources`）跑完后，用本指令让 AI 把当日 raw 素材整理成**当周扫描简报**。
> 触发：`opencode run scan:digest`（或直接在会话里说"生成当周扫描简报"）。
> 参考思路：AIHOT/finhot —— 多源聚类去重 + 热度(命中信源数加权) + 摘要与原文严格分离 + 双时间戳。

## 输入

`scan/<YYYY-MM-DD>/raw/` 目录下的 JSON（由抓取层产出）：

- `_all.json`：当日抓到的全量条目（主输入，去重后）
- `_all_new.json`：当日新增条目（相对历史去重后，供"新增关注"参考）
- `<source>.json`：单源全量（供跨源聚类核对）
- `_summary.txt`：简易汇总（人读用）
- `raw-html/*.html`：官方站/无 RSS 源的原始 HTML 存档（需从中抽取真实条目，不作为独立条目）

## 任务

读取当日 raw 素材，产出《当周扫描简报》（markdown），要求：

### 1. 多源聚类（最重要）
- 同一事件的多源报道聚合成一个 **story**，标题下标注命中信源（如 "via CnEVPost + 东方财富"）。
- 聚类依据：URL 域名 + 标题归一化（去掉日期/数字差异）+ 语义相近。
- 热度标记：命中信源数 ≥2 的 story 标 `[多源]`，单源的标 `[单源]`。多源优先展示。

### 2. 分类（对应三大支柱 + 储能）
- **① 产能地图**：中国电池/材料/设备企业在海外的签约、动工、爬坡、投产、扩产、搁浅。
- **② 政策追踪**：中国出口管制/标准/补贴、美国补贴/关税/许可条款、欧盟法规/护照/反补贴、其他市场政策。
- **③ 市场信号**：装机份额、电芯/材料价格、资本开支、融资、财报、订单合同。
- **④ 储能（筛电池出口相关）**：储能新闻**只保留与中国电池企业出海相关的**（如 CATL/BYD/EVE/HyperStrong 储能电芯或系统在海外的项目、订单、产能、政策影响），归入对应支柱；与电池出口无关的国内储能新闻直接丢弃。

### 3. 横向比对（避免重复选题，重要）

聚类出 story 后，与**网站已产出内容主题索引**（`scan/published-topics.md`）逐条比对，防止产出与已发周刊同主题的重复内容。

- 读取 `scan/published-topics.md`，其中有全部已发期号（No.044–049）的主题画像 + 关键词。
- 每个 story 判断：是否命中某期的主题/关键词？
  - **命中且无新进展** → 标 `[已覆盖 No.0xx]`，移到 ⑤ 弃用区，注明"已有 No.0xx 覆盖，无增量信息"。
  - **命中但含新数据/新进展**（份额更新、新订单、新政策条文）→ 标 `[已覆盖 No.0xx · 有增量]`，仍保留在正文，但摘要里显式注明"相对 No.0xx 的新变化是……"。
  - **未命中任何已发主题** → 标 `[新选题]`，正常保留。
- 关键词比对参照 `published-topics.md` 末尾的"索引使用示例"。

### 4. 每条的字段（严格遵守）
- `标题`（保留原文，不翻译）
- `来源`（信源 key + 层级 S0-S4）
- `发布时间 / 发现时间`（publishedAt / discoveredAt，双时间戳都列）
- `原文链接`（每条必须带，摘要不得脱离原文）
- `AI 摘要`（中文 2-3 句，只做索引；**数字、政策条款、公司原话必须回原文核对后写入**，不确定就标注"待核实"）
- `选题标注`：`[新选题]` / `[已覆盖 No.0xx]` / `[已覆盖 No.0xx · 有增量]`

### 5. 强制溯源（红线）
- 摘要中出现的具体数字、日期、政策名、公司名，必须能在对应原文链接中查到；查不到就删或标"待核实"。
- **不得**把 AI 编造的信息当作已抓取内容写入。

### 6. 输出

写入 `scan/<YYYY-MM-DD>/digest.md`，结构：

```
# 当周扫描简报 — <日期>
> 数据：<N> 条原始 · <M> 个 story · <K> 个多源 · <P> 个已覆盖 · 生成时间

## ① 产能地图
### [多源] story 标题
- 命中信源：...
- 选题标注：[新选题] / [已覆盖 No.0xx · 有增量]
- 时间：发布 X / 发现 Y
- 链接：...
- 摘要：...

## ② 政策追踪
...

## ③ 市场信号
...

## ④ 储能（筛电池出口相关）
...

## ⑤ 待核实 / 弃用 / 已覆盖
- 罗列：无法溯源到原文的、与电池出口无关被丢弃的、以及 [已覆盖 No.0xx] 的条目（一行一条，简要原因）
```

## 完成后

- 向用户报告：生成了几条 story、几个多源、**几个 [已覆盖]（关联到哪期）**、有没有需要人工确认的待核实项。
- **不改动 raw/ 原始数据**，只新增 `digest.md`。
