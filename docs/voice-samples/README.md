# 参考文本库（Voice Samples）

规则写在 `docs/voice.md`，样本放在这里——规则说「不要什么」，样本说「要像什么」。起草前读两段，比读十条规则管用。

## 三类样本

| 类型 | 学什么 | 代表 |
|---|---|---|
| 外部·快讯 | 首句即新闻、数字密度、归属与口径 | CnEVPost |
| 外部·分析 | 预测必须署名、数字带时间窗、判断可证伪 | BloombergNEF |
| 本刊·好评段落 | 我们自己的口吻（由编辑挑选，不是自评） | No. 060 / No. 061 |
| 反例 | 为什么坏，比正面样本更好用 | No. 062 初稿开头 |

## 命名

`<lang>-<source>-<topic>.md`，例如 `en-cnevpost-retail.md`、`zh-cbb-061-take.md`；反例用 `bad-<期号>-<主题>.md`。

## 怎么加一条

1. 新建文件，照现有文件的结构：来源 / 链接 / 日期 / 类型 / 适用规则 / 原文 / 为什么好。
2. 原文只摘 **100–250 词**，不要整篇；外部文本仅作内部参考，链接与日期必须留。
3. 「为什么好」必须落到具体规则（S1、S3、R2……），不要写「读起来很顺」。
4. 在下面的索引表加一行。
5. 如果样本推翻了某条规则，改 `docs/voice.md`，并在修订记录里写清原因——不要让样本和规则打架。
